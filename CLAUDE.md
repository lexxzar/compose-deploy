# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Test Commands

```bash
go build -o cdeploy .          # Build binary
go test ./...                   # Run all tests
go test ./internal/runner/ -v   # Run tests for a single package
go test ./... -count=1          # Run all tests uncached
go mod tidy                     # After adding/removing imports
```

The root command launches a Bubble Tea TUI requiring a TTY, so `cmd/root_test.go` tests flag registration and subcommand structure rather than executing the root command directly.

## Architecture

cdeploy is a dual-mode tool — interactive TUI (no args) or non-interactive CLI (`deploy`/`restart`/`stop`/`rollback`/`list`/`logs`/`exec`/`skill`) — over one three-layer core:

```
cmd/ (Cobra)  →  runner (pipeline orchestrator)  →  compose (docker CLI wrapper)
tui/ (Bubble Tea) ↗
```

**Key abstraction**: `runner.Composer` (`internal/runner/runner.go`) is the seam between the orchestrator and Docker, so the runner is testable with mocks. Three production implementations: `compose.go` local, `remote.go` SSH, `hostcontainers.go` the read-only unmanaged view. Methods: `Stop`, `Remove`, `Pull`, `Create`, `Start`, `ListServices`, `ContainerStatus`, `ContainerStats`, `CheckUpdates`, `Logs`. **Widening the interface means every mock adds a matching no-op** — `grep -rn ") ListServices(" . --include='*.go'` enumerates all of them, production and test (several mock types are not named `*Composer*`, so do not narrow the pattern to the type name).

**Event system**: `runner.Run()` sends `StepEvent` structs through a channel. The CLI consumer (`cmd/deploy.go:runOperation`) prints colored status lines. The TUI consumer (`internal/tui/app.go`) drives a Bubble Tea model through `tea.Cmd` that reads from the channel.

**TUI state machine**: eight screens — `screenSelectServer`, `screenSelectContainers`, `screenProgress`, `screenLogs`, `screenConfig`, `screenInspect`, `screenSettingsList`, `screenSettingsForm` — selected by a `screen` field on ONE flat Model. **GROUPED is a MODE on `screenSelectContainers` (`m.grouped`), never a screen**, and **there is NO project-select screen**: picking a project is a drill-in on the same screen. Container action keys: `r`/`d`/`s`/`R` arm a confirmation (`confirming` + `pendingOp`), `x` arms one too (`pendingExec`, then `tea.ExecProcess`), `l`/`c`/`i` open their screens with none. **`l`/`i`/`x`/`U` are NOT gated on `m.readOnly()`; every write key is.** `esc` — and `q`, rewritten to it on nested screens — resets downstream state; while confirming it cancels without navigating. Entry model, landing sites and the back-navigation cleanup discipline: `docs/architecture/tui-multi-project.md`.

**Exit confirmation for remote connections**: `ctrl+c` quits, **except mid-pipeline on `screenProgress`, where it is a NO-OP**; with a live remote connection (`disconnectFunc != nil`) it PROMPTS instead. `quitting` gates a global intercept at the TOP of `handleKey()` — `y` quits, `n`/`esc` cancels, every other key is SWALLOWED — and `View()` checks it FIRST. **`tryQuit()` is the ONE quit path, never a direct `tea.Quit`**, outside `screenSelectServer` and the `q`-at-root rewrite. Local sessions bypass it entirely. Full rationale, failure modes and test pins: `docs/architecture/tui-help-overlay.md`.

**`?` key-reference overlay**: `?` opens the screen's key list; a flag (`helpOpen bool`), **never a screen constant**. `helpGroupsFor(s, hc helpContext)` builds it; **group ORDER is load-bearing** (`splitHelpGroups` cuts sequentially). **A key or row added moves that variant's width/height thresholds and needs its drift pin extended**; `layoutHelpColumns`/`budgetHelpRows` clamp; **`viewHelp()` must NOT end in a newline**. **Intercept order is load-bearing**: `quitting`, `helpOpen` swallow, `?` open, `q`→`esc`; swallow BEFORE open; `ctrl+c` clears it and FALLS THROUGH. Open gated on `!m.typingInInput() && !m.confirmPromptArmed()` (screen-SCOPED; flat `!m.confirming` is WRONG), and a handler arming a confirmation must clear `helpOpen`. Full rationale, failure modes and test pins: `docs/architecture/tui-help-overlay.md`.

**Container footer and the one-line width guard**: `containerFooter()` and `containerFooterLines()` read `containerHelpLines()`; `svcVisibleCount()` reserves `2 + containerFooterLines()`, and the footer pads every state to the reserved count, advertising ONLY keys the state binds while **the line COUNT stays state-independent**. Guard with `ansi.StringWidth`, **never `len()`**; clamp with `clampToWidth`, never grow the count. Full rationale, failure modes and test pins: `docs/architecture/tui-help-overlay.md`.

**`q` as back key on nested screens**: the 4th `handleKey()` intercept rewrites `q` to `esc` on nested screens — **never add parallel `q` handlers**. `q` quits only on roots: `screenSelectServer`, and containers when `!m.canGoBack() && !m.confirming` (drilled `canGoBack()` IS `m.drilledFromHost`, so `q` quits when it is FALSE). `screenProgress` no-ops `q`/`ctrl+c` while `!done && !failed && !m.waiting`; skipped under `m.typingInInput()`. Full rationale, failure modes and test pins: `docs/architecture/tui-help-overlay.md`.

**Stale async message guard**: a goroutine a screen spawned (e.g. `readLogChunk` for `screenLogs`) can deliver after the user navigated away, so its handler MUST check `m.screen` and discard — otherwise it reads nil fields `esc` cleanup already cleared and panics. Pair the screen check with a monotonic session counter (`logsSession` is the worked example) for every new screen that spawns background goroutines — the counters, their bump sites and the gate recipe are in `docs/architecture/tui-refresh-loop.md`.

**Service list scrolling**: `svcOffset` = the first visible ROW of `m.svcEntries` (a group header costs one, like a service). `svcVisibleCount()` = `m.height - headerLines - footerLines`, **floored at 1 and THEN capped to the row count** (empty list ⇒ 0); **`m.height == 0` returns every row**. **header 3, 4 with captions; footer `2 + containerFooterLines()` +1 per warning row — never 2**: `titleStyle` `MarginBottom(1)` and `helpStyle` `MarginTop(1)` each cost a REAL row, the reserved search-bar line costs NONE. **Indicators REPLACE blank-line content, never add a row.** **`fixSvcOffset()` moves only the WINDOW, `clampSvcCursor()` only the CURSOR**; every gated container key calls `fixSvcOffset()` before its early return (the dispatch clears `m.warning` above the switch, freeing a footer row). **`svcVisibleCount()` IS the `pgup`/`pgdown` step**, read at PRESS TIME ⇒ overshoot by design; `clampSvcCursor()` BEFORE `fixSvcOffset()`; degenerates to end/home when the list fits. **`svcOffset` resets to 0 with `svcCursor` in the DRILLED `servicesMsg` branch and at every landing/drill site, NEVER in the grouped one** (the 5s reload — `restoreCursorRow(cursorRowID())` + `fixSvcOffset()` instead). **Cursor survives by IDENTITY (`svcRowID`), not index** — `docs/architecture/tui-multi-project.md`. Full rationale, failure modes and test pins: `docs/architecture/tui-refresh-loop.md`.

**Container search (search & jump)**: `/` jumps, **never filters**. **Every fold and reload MUST re-derive `searchMatches`** (`computeMatches`); **every departure from `screenSelectContainers` — and the DRILLED `servicesMsg` RELOAD — calls `clearSearch()`**. Two-stage `esc`: clear, then back-nav; typing-`esc` restores by `searchReturnID`. **`searchBarLine()` MUST be ONE physical line** (`clampToWidth`). Full rationale, failure modes and test pins: `docs/architecture/tui-logs-and-search.md`.

**Multi-project host view — grouped vs drilled, the entry model, and `svcKey`**: GROUPED (`m.grouped`, every project plus `(unmanaged)`) and DRILLED share ONE row model, `svcEntry` DERIVED from `svcGroup`. **`m.grouped` is explicit, never inferred from `len(svcGroups)`.** **Folding hides ROWS, never services — read `svcRefs()`.** **Never key state on a ROW INDEX across a rebuild**: selection by `svcKey(proj, svc)`, cursor by `svcRowID`, fold by NAME. **Qualified keys never leave the Model.** Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Multi-project host view — `HostGrouper`, the grouped loader, and the refresh dispatch**: `HostGrouper` = `GroupHostStatus` + `GroupHostStats`: **ONE listing, TWO calls**, joined by the STAMPED `HostEntries` handle. **Every `loadGroups` return carries `groupedPayload`, failures included**; `groupedStatsCmd` CHAINS off the arrival, seam and listing taken from IT at DISPATCH. **The arrival ENDING the cycle clears `refreshInFlight` UNCONDITIONALLY** before the screen check (never `if !chaining { clear }`); only the chaining branch re-arms. As the 5s reload it leaves cursor, selection, fold and search ALONE and DROPS payloads under `m.confirming`. **A host-only group has no `ConfigDir` — `bindProjComposer` refuses it.** Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Multi-project host view — landing, drill-in/out, and action-time composer binding**: **`enterGroupedContainers()` is the ONE landing body** and owns the reset. **Grouped mode holds `m.composer == nil`**; binding is action-time (`bindCursorComposer`/`bindProjComposer`) and **every binder must unbind before staying on or returning to the grouped screen**. **`x` alone keeps its binding across the prompt**, so grouped `readOnly()` reads `allGroupsUnmanaged()`. **The drill-out `esc` arms the third one-shot, `groupCursorPending`**: the visited project's HEADER, only when `projName != ""`, written AFTER `enterGroupedContainers()`; the next payload WITH ROWS spends it. Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Multi-project host view — fold, header aggregates, and grouped rendering**: **Every fold goes through `settleFold`: re-derive `searchMatches`, aim the cursor at the folded group's OWN header.** **`a` alone is FOLD-AWARE** (`eachUnfoldedSelectableRef()`); **every other selection read stays HOST-WIDE — that split IS the safety rule**. **Fold keys (`←`/`→`, `z`) are grouped-only, write-only, DIRECTIONAL; `Z` stays UNBOUND.** **The view LANDS FOLDED once, via the one-shot `groupFoldPending`**: armed in `enterGroupedContainers()` (after `clearContainerScreen()`) and `NewModel`'s grouped branch, spent by `applyPendingGroupFold()` before the re-derives. Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Multi-project host view — batch partitioning and the sequential progress pipeline**: `opBatch{proj, services}`: **an EMPTY slice means ALL services**. `partitionSelection()` walks SCREEN order, skips unmanaged, falls back to the cursor's group when nothing is selected — **GROUPED-only; drilled keeps `warnNoSelection`**. **Each batch owns its events channel**; `handleStepEvent` resolves inside `currentStepRange()`. **Every batch message carries `batchIdx` + `batchSession` captured at DISPATCH**; `batchSession` bumps at INVALIDATION sites only. Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Multi-project host view — updates in grouped mode**: **no automatic scan fires here**: `autoUpdatesAllowed()` = `!readOnly() && !grouped`, `maybeRefreshUpdatesCmd` returns before the cache lookup AND the in-flight guard. **`U` is the only trigger and scans the CURSOR row's group only.** **`updatesMsg` carries `forKey` captured at DISPATCH — never re-derive it.** **`reapplyUpdateVerdicts(results)` replaces the drilled clear-then-hydrate**: one group's scan blanks no other. Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Log streaming / Log follow-aware auto-scroll**: `screenLogs` pipes `Composer.Logs()` via `io.Pipe`. **ZERO new Model fields**: `YOffset` IS the pause state, following ≡ `AtBottom()`: capture BEFORE every content change, `GotoBottom()` only if it held (`logChunkMsg`, `fullReformat()`, `rederiveLogs()`). Full rationale, failure modes and test pins: `docs/architecture/tui-logs-and-search.md`.

**Log formatting**: `w` wrap/`p` pretty-print are independent; `applyLogFormat()` folds only the unscanned tail (`foldNewRawLines`) into `logsFormatted`; toggles/resizes call `fullReformat()`. Full rationale, failure modes and test pins: `docs/architecture/tui-logs-and-search.md`.

**Log search & filter**: `buildMatcher` builds both preds; `logFilterPred`/`logSearchPred` read the COMMITTED regex flag. `logsRawLines` unfiltered, `logsPartial` the tail, **`logsScanned` a RAW-line cursor, NOT a survivor count** — `foldNewRawLines` MUST advance to `len(raw)`. **`setLogViewportContent()` is the sole `SetContent` chokepoint.** **`esc` peels in order**: typing-search → typing-filter → committed-search → committed-filter → leave. `logBarLine()` is ONE clamped line; viewport height `- 7` at the **two log sites**, `- 6` at config — **no blind find/replace**. Full rationale, failure modes and test pins: `docs/architecture/tui-logs-and-search.md`.

**Status refresh**: every return to the container screen re-fetches `ContainerStatus()` via a `statusMsg` so the running/stopped dots reflect what the operation did — follow this whenever an operation changes container state. `statusMsg.err`/`servicesMsg.err` land in `svcErr`, and a successful refresh clears it. Full rationale, failure modes and test pins: `docs/architecture/tui-refresh-loop.md`.

**Server badge**: `serverBadge()` draws a colored inline badge ONLY when `resolveServerColor()` (group color, else own; **nil-guarded on `m.config`**) is non-empty; empty = the plain breadcrumb. **Inline: no extra line, no viewport budget.** **`serverHost`/`serverColor` are set AND cleared alongside `serverName`**, which also keys `projUpdatesCacheKey`. Full rationale, failure modes and test pins: `docs/architecture/remote-and-servers-config.md`.

**Config screen**: `c` opens `screenConfig` with NO confirmation; `ConfigProvider` is type-asserted and an assertion failure makes the key a no-op. `r` toggles raw/resolved, the resolved half LAZY-fetched once and cached; `e` shells out to `$EDITOR` via `tea.ExecProcess`, then re-fetches AND re-validates. `configSession` is the stale-message guard; `esc` clears every `config*` field. Full rationale, failure modes and test pins: `docs/architecture/tui-inspect-screen.md`.

**Inspect screen**: `Inspector` is `tui`-declared and type-asserted; **`i` is NOT gated on `m.readOnly()`**. **`docker inspect` is TOP-LEVEL**: bypass `command()`/`remoteCommand()`. **`buildInspectSummary` is pure; its ZERO VALUE draws no update row**; renders STATE/HEALTH/IMAGE/MOUNTS/ENV, empty omitted, HEALTH off POINTER `State.Health`/`Config.Healthcheck`. **Never truncate**: wrap via `inspectBuilder`/`wrapCells`, not `softWrapLine`. **`push` is the ONE sanitise chokepoint**; raw's `sanitizeInspectRaw` must NOT `ansi.Strip`. `inspectViewportSize()` = `m.height - 6` (NOT logs `- 7`); `setInspectContent()` is the ONE `SetContent` site + `SetXOffset(0)`; **`viewInspect()` must NOT end in a newline**. Full rationale, failure modes and test pins: `docs/architecture/tui-inspect-screen.md`.

**Exec into container**: `x` needs a RUNNING container, arms a confirmation (`pendingExec`), then shells out via `tea.ExecProcess`; `execDoneMsg` resets it and re-fires the whole container fetch batch. **`DefaultExecCommand` probes with `command -v bash >/dev/null 2>&1 && exec bash || exec sh`** — redirecting stderr on the `exec` itself silences bash's stderr for the WHOLE session. Full rationale, failure modes and test pins: `docs/architecture/tui-inspect-screen.md`.

**Docker Compose**: all docker interaction goes through `Compose.command()` / `RemoteCompose.remoteCommand()` — binary from `Standalone`, `CURRENT_UID` set (`uid:gid` local, `$(id -u):$(id -g)` remote) — **EXCEPT the top-level docker commands** (`stats`, `inspect`, `image inspect`, `buildx imagetools inspect`, `manifest inspect`, `pull`, host `ps`), which build their own argv. **`Detect()` must run before first use; `command()` only READS `Standalone`** — `SetStandalone` inherits the verdict, `SetTestHooks` injects doubles. **An empty container slice means ALL services**; the CLI rejects `-a` combined with explicit names. **`ls` goes through `hostCommand`/`remoteHostCommand`: NO `-f`, NO `-p`.** Every `--format json` parser tolerates BOTH the array and NDJSON forms. Full rationale, failure modes and test pins: `docs/architecture/compose-command-and-status.md`.

**Project identity — caller-supplied, never looked up**: identity is what the CALLER supplied (`-p`, or the picker row's `Name`) and is **NEVER re-derived from `docker compose ls`** — that command scans CONTAINER LABELS, which the deploy pipeline itself removes. **THE STORAGE KEY MUST NOT DEPEND ON STATE THE OPERATION BEING SNAPSHOTTED CAN DESTROY.** `canonicalStateName(dir, name)` folds an UNNAMED invocation onto the directory-default key with no host lookup; `stateName()` is the ONE producer of both that key and the `project_name` stamp. **`ListProjects` must carry NO `-f` and NO `-p`** (`hostCommand`/`remoteHostCommand`). Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**Remote SSH**: `RemoteCompose` over a ControlMaster socket (`/tmp/cdeploy-ctrl-{host hash}-{pid}`). `ConnectCmd()` feeds the TUI's `tea.ExecProcess`; `Close()` tears down. **Every remote arg is `shellEscape`d**; **`CURRENT_UID` is evaluated ON THE REMOTE**. `Detect` builds its OWN argv — no `CURRENT_UID`, no `cd`. `tui.Run()` calls `disconnectFunc` on exit. Full rationale, failure modes and test pins: `docs/architecture/remote-and-servers-config.md`.

**Ad-hoc SSH (`-S`/`--ssh`)**: `[user@]host[:port]`, **CLI-ONLY** (root `RunE` and `skill` reject it). **`--server`/`--ssh` are mutually exclusive; `--identity` requires `--ssh`** — `checkRemoteMutex` at the TOP of every `RunE`, before `os.Getwd()`. **`--ssh` requires `--project-dir`**, enforced inside `resolveSSHRemote`, whose **cleanup is ALWAYS non-nil — `defer` it unconditionally**. **Every ssh argv MUST go through `r.sshArgs()`** = `prefix + SSHExtraArgs + "--" + Host + suffix`: **extras immediately BEFORE the host**, never hand-assembled, nil adds nothing, a derived composer COPIES the field. Full rationale, failure modes and test pins: `docs/architecture/remote-and-servers-config.md`.

**Ad-hoc SSH identity (`-i`/`--identity`)**: **only valid alongside `--ssh`; CLI-only.** `config.ParseIdentity` expands `~/` ONLY and requires a REGULAR file `os.Open` also opens; **no mode/0600 check** — `ssh(1)` does that. `resolveSSHRemote` appends `["-i", cleanPath]` AFTER the port args, so every splice site absorbs it with NO change to `internal/compose/remote.go`. Full rationale, failure modes and test pins: `docs/architecture/remote-and-servers-config.md`.

**Config**: `~/.cdeploy/servers.yml` → `Config{Groups, Servers}`. **`Load()` returns an EMPTY config, not an error, when the file is absent**, then runs the idempotent `migrate()` (per-server colors fold onto `Group.Color`, first-server-wins; auto-create ONLY when `len(Groups) == 0`). **`config.ValidColors` is the ONE source of truth** for `Validate()` and the TUI picker; a new color ALSO needs a `colorMap` entry (`internal/tui/styles.go`), or it renders gray. `Validate()` covers groups and group refs too. **`Save()` is atomic** (temp + rename). **SSH options belong in `~/.ssh/config`, except `-i` via `--ssh`.** Full rationale, failure modes and test pins: `docs/architecture/remote-and-servers-config.md`.

**Settings editor**: `screenSettingsList`/`screenSettingsForm`, `s` on the server screen, **only when `m.config != nil`**. `settingsField` 0-3 = the 4 inputs, 4 = the color picker (`typingInInput()`; `confirmPromptArmed()` = `settingsDelete`). **SAVE FIRST, MUTATE ON SUCCESS**: temp `Config` → `Validate()` → `Save()` → only THEN assign `m.config`/`m.servers` and rebuild `m.serverEntries`. **A grouped server's color lives on the GROUP**; `cleanOrphanedGroups` runs on save AND delete. Full rationale, failure modes and test pins: `docs/architecture/remote-and-servers-config.md`.

**Operations**: four, all through `runner.Run()`, differing only in the step list — `Restart` (stop → rm → create → start), `Deploy` (stop → rm → pull → create → start), `StopOnly` (stop), `Rollback` (Restart's shape, **NO Pull**: registry outages are a classic rollback trigger, so offline rollback from local blobs must work). **`Steps()` and `buildSteps()` fold Rollback into the Restart `default:` branch, with Pull gated on `op == Deploy` alone** — a new op landing in that branch inherits the no-Pull shape.

**Wait engine (`--wait` health gate)**: `EvaluateWait` is a **pure reducer** seeded by `NewWaitState`. **Precedence IS the spec**: (1) `Uptime=="restarting"` x3 **FIRST**; (2) unhealthy; (3) `Running==false` after `everRunning`; (4) never-ran x5; (5) `Health!=""` ⇒ ONLY `healthy`; (6) no healthcheck+running ⇒ after `Grace`. **Firm boundary**: 5/6 PASS needs `elapsed <= Timeout`, 1-4 do NOT; pending at `>= Timeout` ⇒ timed out. **`WaitHealthy`'s `WithDeadline(ctx, start+Timeout)` MUST precede ANY blocking call, `ListServices()` included.** Expiry = exit 2, parent cancel = exit 1 (`ctx.Err()` FIRST). Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**`WaitError` exit-2 contract**: non-OK/errored ⇒ `errors.As` = **exit 2**; keep `Unwrap()`; `stop` never waits. Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**Deploy snapshots & the state file**: **Deploy-only**, pre-Stop, from the RUNNING container; `mergeSnapshot`/`existingForMerge` guard writes. **The `canonicalStateName` key must never depend on state the operation destroys**; EMPTY name = dir-only hash. Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**Rollback pipeline & `PrepareRollback` prep / `ExtraComposeFiles` contract**: `runOperationWithPrep`+`rollbackPrep`; a failed pull aborts BEFORE the override; `pull_policy: never`; `ExtraComposeFiles = [main, override]`, main FIRST, cleanup FUNCTION-scoped; **nil = byte-identical argv**. Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**TUI wait phase & `R` rollback (sessions + cleanup)**: `screenProgress`'s wait is PER BATCH; **`clearWaitState` must NOT clear `opContainers`**; `runRollbackCleanup` on LEAVING, NEVER goroutine-deferred. Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**Health checks**: **`svcAgg` is the ONE home of the replica merge rules**, shared by both `ps` readers: `Running` OR, `Health` worst-case, `Created` oldest, **`Uptime` the longest RUNNING replica — never `CreatedAt`, which is OLDER after a restart**. `Health` is `healthy`/`unhealthy`/`starting`/`""`, nothing else. Full rationale, failure modes and test pins: `docs/architecture/compose-command-and-status.md`.

**Multi-project discovery**: `list` without `-C` discovers every project and groups by header; **per-project errors are NON-FATAL** — warn to stderr, skip, continue (an empty `ConfigDir` skips too). `--stats` shares ONE host-wide `docker stats` through `bulkStatsAggregator.ContainerStatsFromBulk`; **a failed host-wide fetch passes a NON-NIL EMPTY map, never nil** — nil re-runs `docker stats` once PER PROJECT. Full rationale, failure modes and test pins: `docs/architecture/compose-command-and-status.md`.

**Resource stats**: `runner.ServiceStats` comes from host-wide `docker stats --no-stream --format json`. **`AllContainerStats`/`AllContainerStatsRemote` BYPASS `command()`/`remoteCommand()`** — top-level docker, so `command()` would emit `docker compose stats`. Join by SHORT container ID (12 chars) against the project's `ps -a`, **summed across replicas**; stopped services are absent. **`parseSize`/`parseCPUPercent`/`FormatBytes` live only in `internal/compose/stats.go`.** **DRILLED batches status and stats in PARALLEL; GROUPED is strictly SERIAL** — `statsRefreshCmd()` is nil there and `groupedStatsCmd` CHAINS off the `servicesMsg` arrival whose listing it consumes. A singleton 5s `refreshTickMsg` re-fetches both halves while the user lingers; see `docs/architecture/tui-refresh-loop.md`. Full rationale, failure modes and test pins: `docs/architecture/compose-command-and-status.md`.

**Update detection — tri-state and Composer contract**: `UpdateAvailable *bool` is a tri-state (`nil` = unknown/build-only/error): an absent `CheckUpdates` key MUST stay absent; **a non-nil error makes the map untrusted**. Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Update detection — digest comparison**: `fetchRemoteDigestVia` is imagetools-first, `manifest inspect` fallback; inspects **bypass `command()`/`remoteCommand()`**. **Do NOT re-add `--format '{{.Manifest.Digest}}'` to `imagetoolsInspectArgs`** (silently ignored; `Name:` then parses as the digest) **nor a bare-sha256 fallback to `parseImagetoolsDigest`.** Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Update detection — SSH transport classification (RemoteCompose only) / systemic-failure cascades**: `sshTransportStderrPatterns` is SSH-ONLY — **never add generic networking phrases**. One loop, `scanImageUpdates`; **the sentinel it emits picks the cascade — no flag**. Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Update detection — TUI caching and refresh**: `updateCache` is keyed by `projUpdatesCacheKey`; `forKey` travels from DISPATCH and **must never be re-derived**. **Errors ARE cached**, `errMsg` restored on hit, a successful Deploy/Restart/Rollback invalidates it. Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Update detection — sessions and in-flight discipline**: **`updateInFlight` clears BEFORE BOTH the session AND screen checks, on EVERY arrival**; a site bumping `updatesSession` MUST reset it before `maybeRefreshUpdatesCmd()`. Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Update detection — rendering, CLI, and JSON**: `hydrateUpdates` **MUST skip a verdict absent from `m.svcStatus`**; `maxName += 2` **unconditionally**, in TUI and CLI. `--updates` gates the CLI check; failures SET `updates = nil`. Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Update detection — inspect detail rows (`UpdateDetailer`)**: Details are a SECOND message after the cache write — **never fold it into `refreshUpdates`' goroutine, gate `U` on it, or delay the `updateInFlight` clear**. **`detailsInFlight` bounds the phase to ONE batch GLOBALLY**, cleared ONLY on EVERY arrival (`updateDetailsTimeout` guarantees one), **reset by no context-change site**. **A lost batch heals from the ENTRY, never a fourth guard**: `refillUpdateDetailsCmd` on a fresh non-errored entry whose `details == nil` (nil ≠ empty map), two sites, ungated. **`updateDetailsMsg` carries NO session** — `forKey`+`forEntry` from DISPATCH, never re-derived; a detail failure is **DISCARDED, never `updatesMsg.err`**. `localProbeFormat` **names no field**, every doubt in `parseIndexPlatformDigest` **ABORTS**, and **never re-add the lone-QUALIFIED variant fallback**. Full rationale, failure modes and test pins: `docs/architecture/update-detection.md`.

**Session filters for stale responses**: `statsMsg`, `statusMsg` AND `servicesMsg` carry a `session uint64` stamped at DISPATCH; every handler gates on screen AND session. Two counters cover the container screen:
- `statsSession` covers `refreshStats` AND the chained grouped `groupedStatsCmd` — one fetch in two modes. `statusSession` covers `refreshStatus`, `loadServices` AND `loadGroups`: the last two are the initial-load siblings of the first, so they share the counter. `projectsSession`/`projectsMsg` are GONE with the project picker.
- **Both bump at the SAME SEVEN sites, through the ONE helper `bumpFetchSessions()`** (`statsSession`/`statusSession`/`updatesSession`/`rollbackFetchSession` together — never four hand-written `++`): `execDoneMsg`, the `entryLocal` fast track, `esc` from logs, `esc` from progress, `enterGroupedContainers()`, `drillIntoGroup()`, `backToServerScreen()`. **The grouped cycle CROSSES the two** (the arrival passes its `statusSession` gate, then chains a stats fetch stamped `statsSession`), so a site bumping only one has the chained `statsMsg` dropped at a gate that does NOT clear `refreshInFlight` — the exact latch.
- **The two LONE `rollbackFetchSession++` sites (`R`, the `connectResultMsg` FAILURE path) are NOT context changes** and keep their single bump. The SUCCESS path DOES bump all four via `enterGroupedContainers`: it lands on LIVE data, and the site that starts fetching invalidates what a previous server left in flight.

**A NEW async msg tied to a screen context gets a session and a `m.screen != <its-screen> || msg.session != m.<sessionField>` gate.** Full rationale, failure modes and test pins: `docs/architecture/tui-refresh-loop.md`.

**`refreshInFlight` prevents fetch stacking**: tea batches run CONCURRENTLY, so the tick schedules the next 5s tick BESIDE the current fetch; unguarded, a slow `docker stats` stacks pairs. Armed at every dispatch site (tick, the 5 `containerFetchBatch` transitions, `enterGroupedContainers`, both non-server `NewModel` branches) and at the grouped `servicesMsg` branch that CHAINS the stats half. **Cleared on EVERY current-session arrival BEFORE the screen check** — `statsMsg`, and identically at the top of the grouped `servicesMsg` handler. **Never `if !chaining { clear }`**: it skips the stale-session, off-screen, `m.confirming` and `msg.err` paths and LATCHES the guard. Only the chaining branch re-arms; a STALE arrival must not touch it; `backToServerScreen()` resets it false. **The tick's liveness check is `m.composerFactory != nil` GROUPED, `m.composer != nil` drilled.** Full rationale, failure modes and test pins: `docs/architecture/tui-refresh-loop.md`.

**Test seam for the tick**: `Model.tickCmdOverride` is nil in production; tests call `installFakeTick(&m)` so none leaks a real 5s `tea.Tick` goroutine. **`NewModel` arms `refreshInFlight` in BOTH non-server branches** — clear it to test the unblocked tick. Full rationale, failure modes and test pins: `docs/architecture/tui-refresh-loop.md`.

A new screen that should NOT refresh periodically needs no change (the gate excludes every screen but `screenSelectContainers`); one that DOES needs its OWN tick and msg type, never an overload of `refreshTickMsg`. **A new context-change handler calls `bumpFetchSessions()`**, and sets `refreshInFlight` (true if it fires a batch, false if it only navigates away). A stats error keeps status intact in both front ends; slot priority **`svcErr` > `statsErr` > `updatesErr`**. Full rationale, failure modes and test pins: `docs/architecture/tui-refresh-loop.md`.

**Ports column**: `ServiceStatus.Ports` comes from `Publishers[]`, with `parsePortsString()` on the `Ports` text as the fallback when that yields NOTHING. **`PublishedPort == 0` is SKIPPED.** **Dedup is on the FULL tuple `(Host, HostPort, ContainerPort, Protocol)`** so two real binds survive; **`collapseIPv6Mirrors` drops ONLY the `::` half of a `0.0.0.0`/`::` pair** — `::1`, `fe80::1` and explicit IPv6 stay. `FormatPort` hides wildcard hosts, brackets IPv6, arrow U+2192, `/proto` only when non-`tcp` — **DISPLAY only; JSON keeps the original `host`**. Ports renders LAST, and **a blank cell means NO PORTS, not "stopped"**. Full rationale, failure modes and test pins: `docs/architecture/compose-command-and-status.md`.

**Unmanaged containers — the `HostContainers` composer and the three-method `dockerRunner` seam**: label-less containers get read-only `compose.HostContainers`: writes `return errReadOnly`, reads use the 3-method `dockerRunner` seam (`run`/`stream`/`tty`). **Both `hostPsArgs` and `hostStatsArgs` take the `{{json .}}` TEMPLATE form and name NO field** (an unknown field is a hard template error); `--size=false` is on `hostPsArgs` ONLY — never add it to `hostStatsArgs`, and the ps/stats equivalence is PER-COMMAND; `isComposeManaged` matches the label key at a token start ONLY; `Running` keeps its `"Up "` fallback. Full rationale, failure modes and test pins: `docs/architecture/unmanaged-containers.md`.

**Unmanaged containers — the `(unmanaged)` group, the widened `ComposerFactory`, and the cache-key collision**: `compose.Project.Unmanaged bool`; `buildSvcGroups` is the SOLE producer of the `(unmanaged)` group; `unmanagedrow.go` is deleted, keep `UnmanagedProjectName`. **`ComposerFactory` takes a `compose.Project`**: carry `Name` into `ProjectName` and `ConfigFiles` into `ComposeFiles` (`PinComposeFilesLocal`/`PinComposeFiles`), copy `SSHExtraArgs`. **`projUpdatesCacheKey` is the ONE key producer**: `ConfigDir+NUL+Name+"|"+serverName`, `"unmanaged|"`-prefixed. Full rationale, failure modes and test pins: `docs/architecture/unmanaged-containers.md`.

**Unmanaged containers — the read-only UI contract**: `ReadOnlyComposer` needs a **named** `ReadOnlyComposer() bool`. `d`/`r`/`s`/`R`/`c`/`space`/`a` early-return, **each calling `fixSvcOffset()` first**; `c`/`R` gate explicitly. **Nothing advertises a no-op**: `containerHelpLines()`/`readOnlyContainerGroups` own the read-only footer and help tables. **No automatic update check**: all three auto entry points read `autoUpdatesAllowed()` (`!readOnly() && !grouped`); `U` is the only trigger. Full rationale, failure modes and test pins: `docs/architecture/unmanaged-containers.md`.

**Grouped host view — label-derived names are UNTRUSTED**: names come from container LABELS; the 5s redraw replays whatever they hide, unprompted. `sanitizeName` IS `sanitizeInspectLine` — `ansi.Strip`, then drop BEL, CR, DEL and the 8-bit C1 controls (**never a second mechanism**), applied at INGESTION in `buildSvcGroups`, `setSingleGroup` and **`svcKey` (BOTH halves)**, never at render. **On a collision the name needing NO sanitizing wins.** Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Grouped host view — a lone group that draws no rows KEEPS its header**: `groupsHaveHeaders` is "more than one group", plus one exception `len(groups) == 1 && (folded || no services)`: ZERO rows means no cursor and nothing to unfold or operate on. Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**Grouped host view — an `svcErr` makes every row key inert**: `viewSelectContainers` early-returns an error screen that hides the rows but KEEPS the groups and selection: **the dispatch swallows every key but `esc` and `ctrl+c` while `m.svcErr != nil`**. Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.

**`rollbackPreppedMsg` carries batch identity**: `batchIdx`+`session` captured at DISPATCH; gate on screen+idx+session; stale branches MUST invoke `msg.cleanup`. Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

**`Compose.ProjectName` / `RemoteCompose.ProjectName` (`-p` splice)**: a composer built from a directory ALONE addresses that directory's DEFAULT project, not the `-p`-named one sharing it — `d`/`r`/`s` removed another project's containers. `projectNameArgs`/`RemoteCompose.projectFlag` splice `-p <name>` **AFTER the `-f` pairs and before the subcommand** (that order keeps the `ExtraComposeFiles` rule untouched), shell-escaped on remote, and **`RemoteCompose.ExecCommand` must splice it too** because it builds its own argv. **An empty name must keep producing byte-identical argv.** Five sites stamp it and **none looks it up** — see the project-identity paragraph. Full rationale, failure modes and test pins: `docs/architecture/compose-command-and-status.md`.

4. Gate the new key on `m.readOnly()` with an early return, and leave it OUT of `readOnlyContainerGroups()` (`internal/tui/help.go`) — every operation is a compose pipeline, so a new op is inert on the read-only screen by definition: `docs/architecture/unmanaged-containers.md`
4b. **Route the key through the GROUPED path, or it writes a nil deref**: arm through `armOperation` / `partitionSelection()`, bind with `bindProjComposer(batches[0].proj)` at the confirming `enter`, and call `unbindGroupedComposer()` on EVERY early return between the two. Add the grouped dispatch test beside the drilled one. **A GROUPED-ONLY key must also be added to the hand-maintained `groupedOnly` map in `TestHelpGroups_GroupedNamesTheSameKeys`** (`internal/tui/help_test.go`); a key bound in both modes needs no second list. Why: `docs/architecture/tui-multi-project.md`
5. Add CLI subcommand in `cmd/deploy.go` and register in `cmd/root.go`
6. Tests: runner sequence test, cmd subcommand/flag tests, TUI action key + confirmation tests, the expected-key set in `TestHelpGroups_NamesEveryBoundKey` (`internal/tui/help_test.go`, which fails in BOTH directions), and — for a WRITE — the key in `TestReadOnly_GatesWriteKeys` (`internal/tui/app_test.go`), pinning the gate step 4 added. **`TestHelpGroups_ReadOnlyNamesEveryBoundKey` needs NO edit for a gated key**: `docs/architecture/unmanaged-containers.md`.

If the new operation needs an op-specific pre-run step (Rollback's snapshot read + digest-pin prep), don't fork `runOperation` — route through `runOperationWithPrep(ctx, op, all, containers, prep)`. `prep func(context.Context, runner.Composer) (func(), []string, error)` runs AFTER the composer is built and BEFORE the pipeline, so it can refuse and configure (e.g. `ExtraComposeFiles`); its cleanup is deferred FUNCTION-scoped, landing after the wait phase but before the SSH teardown (LIFO). **The `[]string` is the RESOLVED target set and drives BOTH the pipeline and the wait gate** — a non-empty return replaces `containers`, which is nil under `-a` and would otherwise sweep in every compose service. deploy/restart/stop pass a nil prep. Rollback lives in `cmd/rollback.go` but is a reuse of this machinery, not a fresh subcommand skeleton. Full rationale, failure modes and test pins: `docs/architecture/wait-snapshots-rollback.md`.

## Adding New CLI Subcommands

See `cmd/list.go`, `cmd/logs.go`, and `cmd/exec.go` for the pattern. Each subcommand:
1. Creates a `*cobra.Command` in its own `new*Cmd()` function
2. Calls `checkRemoteMutex(serverName, sshTarget, identityFile)` at the TOP of `Run*` — **before `os.Getwd()` and `signal.NotifyContext`**, so conflicting flags run no setup
3. Branches in THIS order: `sshTarget != ""` → `resolveSSHRemote(ctx, sshTarget, projectDir, projectName, identityFile, <factoryVar>)`; else `serverName != ""` → `resolveServerRemote(ctx, serverName, projectDir, projectName, <factoryVar>)` — or the inline equivalent, which only `cmd/list.go` needs because host-wide discovery must IGNORE `server.ProjectDir`; else local `compose.New(dir)` through **`prepareLocalComposer(ctx, lc, projectName)`**. Each `<factoryVar>` is the subcommand's own injectable remote factory, preserving its test seam. **All three paths take the project name as a PARAMETER and stamp it; none looks it up** — see the project-identity paragraph
4. Is registered in `cmd/root.go` via `rootCmd.AddCommand()`

Two deliberate exceptions. `cmd/skill.go` has no remote branch at all: it writes local user-level files, and its parent `PersistentPreRunE` REJECTS `--server`/`--ssh`/`--identity`/`--project-dir` rather than ignoring them (`docs/architecture/skill-distribution.md`). `cmd/rollback.go` reuses the deploy machinery instead of the skeleton — `runOperationWithPrep(ctx, runner.Rollback, …, rollbackPrep(…))` already does the mutex check and the ssh/server/local branching; see "Adding New Operations" for the prep-hook recipe.

## Agent Skill distribution

`cdeploy skill install|show|uninstall <claude|codex|all>` writes the embedded `skills/cdeploy/SKILL.md` into claude → `~/.claude/skills/cdeploy`; codex → `~/.agents/skills/cdeploy` AND `$CODEX_HOME/skills/cdeploy` (default `~/.codex`, **EMPTY = unset**); all → the deduped union. **Install never trusts a file it did not write, and that takes TWO checks**: `verifySkillFile` answers only "consistent with its OWN stamp?", so the decision also needs `bytes.Equal(stripOwned(onDisk), canonical)` against THIS binary's bytes — without both, `unchanged` is unreachable; modified or unstamped is REFUSED without `--force`. **The stamp goes immediately before the frontmatter's CLOSING `---`** (`frontmatterCloseOffset`, never a bare `---`) — the frontmatter must stay the FIRST bytes — and **the canonical frontmatter carries NO `metadata:` key**. Full rationale, failure modes and test pins: `docs/architecture/skill-distribution.md`.

## Package Coupling

The TUI package depends on `runner.Composer` (interface), not `compose.Compose` or `compose.RemoteCompose` (concrete). For operations that need to create a `Composer` at runtime (drilling into a group, or an action key binding the cursor row's project), use a `ComposerFactory` callback injected from `cmd/` — this keeps `tui` decoupled from `compose`. The factory takes the whole `compose.Project`, not a directory string, so it can branch on `proj.Unmanaged` and return the read-only `compose.HostContainers` for the synthetic `(unmanaged)` group. That same branch is how the grouped host view reaches its host-wide seam: `composerFactory(compose.Project{Unmanaged: true})` type-asserted to `HostGrouper`, so no signature had to widen. Similarly, `ProjectLoader` and `ConnectCallback` are injected by `cmd/` for remote server support. The `compose` package has the `HasComposeFile` package-level function for local compose file detection; project discovery (`ListProjects`) is a method on `Compose`/`RemoteCompose` requiring `Detect()` first. The `ConfigProvider` and `ExecProvider` interfaces are defined in `tui` (not `runner`) because they return `*exec.Cmd` and are TUI-only; the TUI type-asserts `composer.(ConfigProvider)` and `composer.(ExecProvider)` at runtime — no separate factory or wiring needed. `ReadOnlyComposer` is the same shape and the same reason: only `compose.HostContainers` implements it, and a composer that omits it renders the normal writable screen. `Inspector` — and `ExecProvider` with it — is the same shape with the reach inverted: ALL THREE composers implement both, so `i` and `x` are live on every container screen and the type assert exists for test mocks rather than for a capability split. `ConfigProvider` is the one of the three with a real capability split: `HostContainers` omits it, so `c` is gated. `UpdateDetailer` is `Inspector`'s twin: all three composers implement it, it is asserted the same way, and a composer that omits it simply renders no update rows. `HostGrouper` (two methods over one listing, `GroupHostStatus`/`GroupHostStats`) is the same shape with the narrowest reach: only `compose.HostContainers` implements it, and a factory that cannot produce one yields a grouped screen with projects but no status — not an error.

## Testing Approach

Tests use stdlib `testing` only — no testify or other test frameworks.

- `internal/runner/`: Mock `Composer` interface to verify step sequences and failure behavior without Docker
- `internal/compose/`: Test command construction (args, env vars, flags) without executing commands; `parseProjects()`, `parseContainerStatus()`, `parseStatsOutput()`, `parseSize()`, `parseCPUPercent()`, and `FormatBytes()` extracted for testability; `RemoteCompose` tests verify SSH arg construction and shell escaping; `inspect_test.go` drives `pickInspectContainer`/`pickHostInspectContainer`, `parsePsEntries` and `ParseInspect` against three real `docker inspect` fixtures, and asserts the inspect argv carries no `compose`; `hostcontainers_test.go` drives `HostContainers` through a fake `dockerRunner` (the same seam production uses), so every read method is testable without Docker and the remote adapter's `SSHExtraArgs`-before-host splice is pinned directly; `updatedetails_test.go` drives the four-step detail fetch through that same seam, against real registry captures in `testdata/imagetools_*.json` plus a real `docker image inspect` document in `testdata/image_inspect_nginx.json` (the one thing a hand-authored fixture cannot pin is docker's KEY SPELLING) — **no test may hit a registry**, since a suite that did would reproduce the 429 in CI
- `internal/config/`: Test YAML parsing, validation, and lookup with temp files
- `internal/tui/`: drive `Update()` with `tea.KeyMsg` directly — no TTY. **Every container-screen test goes through the fixture helpers**: `singleGroupModel` / `groupedModel` + `svcGroupOf` / `selectedIdx` / `qStatus` / `qStats` / `qk` / `progressStep`. **There is no `services` field on Model** — a flat name list comes from `modelServices(m)`. New tests belong in the file that owns the subsystem, never in `app_test.go` again: `grouped_test.go` (the grouped host view), `batch_test.go` (multi-batch progress), `entries_test.go` (the pure row model), `format_test.go`, `inspect_test.go`, `help_test.go` (the `?` overlay). Full rationale, failure modes and test pins: `docs/architecture/tui-multi-project.md`.
- `internal/logging/`: Use `t.TempDir()` for file creation tests
- `skills/`: content pins on the embedded `cdeploy/SKILL.md` — frontmatter FIRST, `name` matches the dir + the regex, description ≤1024 chars, under 500 lines, **no `metadata:` key**: `docs/architecture/skill-distribution.md`
- `cmd/`: Test flag registration, subcommand existence, and validation via `NewRootCmd()`; `cmd/skill_test.go` uses `t.Setenv` HOME/CODEX_HOME (never `t.Parallel`) for the path matrix, symlink dedupe, and the install/uninstall decision matrix in a temp HOME (render/verify round-trip is pure)
